Revisión por lectura de código, no ejecución de cargadores, 2026-11-15. Todos los comandos Python de este documento suponen `backend/` como directorio y su Python 3.12 activo; usar `.venv/Scripts/python.exe` en lugar de `python` si no se activa el entorno. Las rutas de archivos se expresan desde la raíz del repositorio.

**Los comandos de escritura siguientes son referencias de auditoría, no pasos autorizados de instalación. No ejecutarlos durante la recepción.** Ningún cargador se ejecutó para preparar esta documentación. Comprobado por revisión estática no equivale a validado contra datos reales ni a idempotencia probada en la principal.

## Convenciones para los comandos SQL

Para cada archivo SQL identificado abajo, la invocación técnica completa en PowerShell es:

```powershell
psql -X -W -h 127.0.0.1 -p 5432 -U postgres -d esart_db -v ON_ERROR_STOP=1 -f <ruta-exacta-del-archivo>
```

Sustituir únicamente el argumento de archivo por la ruta exacta de su fila, desde la raíz; el propietario local debe confirmar su cuenta. Alternativa DBCode: seleccionar esart_db/propietario, abrir ese archivo y ejecutar todo en la misma conexión. No poner contraseñas en línea de comandos. Para los archivos históricos el destino técnico es el indicado en su fila, **pero no está autorizado conectar o cargar esas bases ahora**. Si un archivo incluye una transacción propia, no envolverlo en otra sin revisión. Confirmar COMMIT, no solo NOTICE; ante ERROR, detenerse y ROLLBACK.

Requisitos generales de cualquier escritura futura: respaldo recuperable, identidad, esquema exacto, privilegios de objeto y aprobación específica. La validación mínima posterior es el SQL de la [guía PostgreSQL](ESART_INSTALACION_BASE_DATOS.md), comparación de valores existentes y repetición controlada. Nunca repetir un script desconocido para averiguar qué hace.

## Balance de procedimientos

Comprobados en esta entrega: carga de metadatos/modelos en pruebas, lectura real de cuatro catálogos como esart_aplicacion, conteos y FUTOM, historial/head de código, pytest offline, Ruff, compilación Python, build y pruebas Angular. No se ejecutó una carga para demostrar idempotencia actual.

Pendientes: instalador desde cero, seed principal completo separado del DDL, repetición transaccional contra principal con aprobación, autenticación real/HTTP/Angular, restauración verificable del respaldo actual y revisión de secretos heredados antes de publicación. Los JSON de pruebas históricas conservan valor de evidencia limitado a su destino y fecha.
